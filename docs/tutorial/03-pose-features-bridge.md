# 03. Pose Features 연결 흐름

> 상태: 초안
> 관련 이슈/PR: #5, #6, #8, #9

## 이 장의 목표

이 장에서는 Hand Tracking Spike에서 만든 관절 좌표가 Pose Features 계산으로 어떻게 이어질 수 있는지 정리한다.

중요한 점은 현재 두 코드가 앱 타깃 안에서 종단 간으로 연결된 상태는 아니라는 것이다. 현재 단계에서는 PR #8 댓글 기준으로 자료형과 좌표 흐름이 연결 가능한 구조임을 확인한 상태다.

## 연결 흐름 요약

튜토리얼에서는 다음 흐름으로 설명할 수 있다.

```text
HandAnchor
→ HandTrackingSnapshot
→ HandJointSample.originFromJointTransform
→ SIMD3<Float> position
→ Pose Features 입력
→ 손 모양 판정 재료
```

`HandTrackingService`는 ARKit의 `HandAnchor`를 직접 다룬다. Pose Features 계산은 ARKit과 RealityKit에 직접 의존하지 않고, `SIMD3<Float>` 위치 값을 입력으로 받는 방향이 적합하다.

이렇게 분리하면 손 추적 입력이 실제 기기에서 들어오는지와 별개로, Pose Features 계산은 합성 좌표 테스트로 검증할 수 있다.

## #8에서 제공하는 입력 재료

PR #8의 Hand Tracking Spike는 다음 정보를 Pose Features 단계로 넘길 수 있는 형태로 정리한다.

- 왼손/오른손 구분
- 손 전체 추적 상태
- 관절 이름
- 관절별 추적 여부
- 관절별 월드 transform

Pose Features 쪽에서는 `originFromJointTransform.columns.3`에서 위치 값을 꺼내 `SIMD3<Float>` 입력으로 사용할 수 있다.

## #6이 기대하는 입력 정책

PR #8 댓글 기준으로, #6 Pose Features는 현재 25개 주요 관절 입력을 요구하는 정책으로 정리되어 있다.

- PR #8의 관절 catalog 27개 중 `forearmArm`, `forearmWrist`를 제외한 25개가 #6 특징 계산 입력과 이름 단위로 대응한다.
- 현재 #6은 손바닥 크기, 다섯 손가락의 직진도, 굽힘, 손목-손끝 거리 등을 한 번에 계산한다.
- 따라서 25개 필수 관절 중 하나라도 빠진 프레임은 `missingJoints`로 보고 특징 계산을 건너뛰는 것이 현재의 안전한 정책이다.
- 누락 관절을 영점 좌표로 채우지 않는다.

## 왜 영점 좌표로 채우지 않는가

추적되지 않은 관절을 `(0, 0, 0)` 같은 임의 좌표로 대체하면 계산은 계속될 수 있지만, 결과는 실제 손 모양과 무관한 값이 된다.

예를 들어 손끝 관절 하나가 누락되었는데 영점 좌표로 대체하면 다음 값들이 모두 왜곡될 수 있다.

- 손목-손끝 거리
- 손가락 직진도
- 손가락 굽힘 각도
- 손바닥 크기 정규화 값
- 양손 사이 거리와 방향

그래서 현재 정책은 "없는 데이터를 만들어서 판정하지 않는다"에 가깝다.

## 튜토리얼에 넣을 요약 문장

현재 Hand Tracking Spike가 제공하는 좌우 손 구분, 추적 상태, 관절 이름 및 월드 transform은 Pose 특징 계산 입력으로 변환 가능한 구조임을 합성 좌표와 visionOS 빌드로 확인했다. 다만 실제 관절 확보율, 좌표 특성, 정규화 값과 자세별 임계값은 Apple Vision Pro 실기기 입력으로 재검증해야 한다.

주의사항에는 다음 문장을 함께 둔다.

> 추적되지 않은 관절을 영점 좌표로 대체하지 않으며, 현재는 25개 필수 관절이 누락된 프레임의 특징 계산을 건너뛴다.

## 실기기 전까지 남아 있는 불확실성

- 실제 손에서 25개 필수 관절이 동시에 확보되는 비율
- 손 가림과 빠른 움직임에서 관절별 추적 손실 빈도
- 실제 월드 좌표의 방향, 단위, 좌우 손 법선 보정 결과
- 실제 손 크기 차이에 대한 정규화 안정성
- 술, 인, 축 포즈별 특징값 범위와 판정 임계값
- smoothing, 히스테리시스, 자세 유지 시간의 필요성

## 이후 구현으로 이어질 작업

문서화 다음 단계에서는 #5와 #6을 앱 안에서 종단 간으로 연결하는 별도 Spike가 필요하다.

그 작업에서는 다음을 확인해야 한다.

- `HandTrackingSnapshot`을 Pose Features 입력 타입으로 변환하는 어댑터 위치
- 25개 필수 관절 정책이 실제 프레임에서 너무 엄격하지 않은지
- 포즈별로 필요한 관절만 요구하는 정책이 필요한지
- UI에서 특징값과 누락 관절을 어떻게 표시할지

## 이 장의 완료 기준

- Hand Tracking 출력이 Pose Features 입력으로 어떻게 변환되는지 설명할 수 있다.
- 현재 연결 가능성이 확인된 범위와 아직 연결되지 않은 범위를 구분할 수 있다.
- 누락 관절을 임의 좌표로 채우지 않는 이유를 설명할 수 있다.
- 실기기 검증 전 남아 있는 불확실성을 설명할 수 있다.
