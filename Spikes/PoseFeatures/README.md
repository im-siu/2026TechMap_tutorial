# Pose Features Spike

관련 Issue: [#6 Pose 판정용 특징값 계산 방식 검증하기](https://github.com/im-siu/2026TechMap_tutorial/issues/6)

## 확인한 질문

ARKit과 실기기 입력 없이도 관절 월드 좌표를 받아 펼친 손, 주먹, 핀치와 양손 관계를 설명할 특징값을 순수 Swift로 계산하고 재현 가능한 테스트로 검증할 수 있는가?

이 Spike는 **특징값 계산까지만** 다룬다. Pose 분류, 임계값 확정, smoothing, 히스테리시스와 UI는 포함하지 않는다.

## 입력 계약

`HandSample`은 다음 두 값만 받는다.

- `side`: `.left` 또는 `.right`
- `joints`: `HandJoint`를 월드 공간의 `SIMD3<Float>` 위치에 연결한 Dictionary

`HandJoint` 이름은 Apple의 [`HandSkeleton.JointName`](https://developer.apple.com/documentation/arkit/handskeleton/jointname)과 일치시켰다. 특징 계산에 사용하지 않는 `forearmArm`, `forearmWrist`는 입력에서 제외했다.

모든 특징에 필요한 관절이 없으면 `missingJoints` 오류를 반환한다. NaN·무한대 위치, 영에 가까운 손바닥 크기·평면, 길이가 0인 손가락 뼈도 각각 명시적인 오류로 반환한다. 임의의 0 좌표로 대체하지 않는다.

## 계산한 특징

### 손 크기 정규화 후보

| 후보 | 계산 | 장점 | 한계 |
| --- | --- | --- | --- |
| 손바닥 너비 | 검지–새끼손가락 metacarpal 거리 | 손가락 굽힘의 영향을 적게 받음 | 손가락 벌림과 관절 노이즈의 영향 가능 |
| 손바닥 길이 | 손목–중지 metacarpal 거리 | 설명과 계산이 단순함 | 짧은 기준선이라 위치 오차의 상대 영향이 큼 |
| 기하평균 | `sqrt(너비 × 길이)` | 두 축을 함께 반영하고 균일 스케일에 선형 비례 | 실제 손에서 어느 후보가 안정적인지는 미검증 |

프로토타입은 세 값을 모두 노출하고, 거리 정규화의 임시 기준으로 기하평균을 사용한다. 이 선택과 임계값은 실기기 데이터 확인 전에는 확정하지 않는다.

### 한 손 특징

- 손바닥 중심: 손목과 네 손가락 metacarpal 위치의 평균
- 손바닥 법선: 검지→새끼손가락 너비 벡터와 손목→중지 길이 벡터의 외적. 왼손은 부호를 반전해 거울 자세의 좌우 손이 같은 방향을 갖도록 한다.
- 손가락 직진도: 첫 관절–손끝 직선거리 ÷ 모든 뼈 구간의 경로 길이. 1에 가까울수록 곧다.
- 굽힘 각도: 인접한 정규화 뼈 벡터 사이의 각도. 0에 가까울수록 곧다.
- 손끝 거리: 손목–각 손끝의 절대거리와 기하평균으로 나눈 거리
- 핀치 후보: 엄지 끝–검지 끝의 절대거리와 정규화 거리

합성 좌표에서 검지 직진도는 펼친 손 `1.00`, 부분 굽힘 약 `0.86`, 주먹 약 `0.39` 순서였다. 펼친 손의 정규화 손목–검지 끝 거리는 약 `2.59`, 주먹은 약 `1.10`이었다. 핀치 합성 좌표의 정규화 엄지–검지 거리는 약 `0.020`으로, 펼친 손의 약 `1.77`보다 작았다. 이 값은 합성 데이터의 관찰값이지 실제 판정 임계값이 아니다.

### 양손 특징

- 두 손바닥 중심의 절대거리
- 두 손의 기하평균 크기를 다시 평균한 값으로 정규화한 중심 거리
- 왼손 중심에서 오른손 중심으로 향하는 단위 방향
- 손바닥 법선의 내적과 각 손바닥이 상대 손을 향하는 정도

두 중심이 일치하면 거리는 `0`이고 방향과 마주 보기 점수는 `nil`이다. 정의할 수 없는 방향을 0 벡터로 만들지 않으므로 NaN이 발생하지 않는다.

## 합성 좌표와 테스트 결과

테스트 fixture는 펼친 손을 기준으로 다음 변형을 만든다.

- 네 손가락을 손바닥 쪽으로 되접은 주먹
- 검지만 중간 정도 굽힌 경계 사례
- 엄지 끝을 검지 끝 가까이 옮긴 핀치
- 평행이동, Y축 회전과 1.8배 균일 스케일을 함께 적용한 같은 자세
- X축을 반전한 왼손
- 크기가 다른 양손, 서로 마주 보는 양손과 중심이 일치하는 양손
- 관절 누락, 무한대 위치, 0 너비 손바닥과 중복 관절

실행 환경과 결과:

```text

Xcode: 26.6 (17F113)
Swift: 6.3.3
명령: DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun swift test --package-path Spikes/PoseFeatures
```

다음 항목을 통과했다.

- 평행이동·회전·균일 스케일 뒤 직진도, 굽힘 각도와 정규화 거리 유지
- 펼친 손 > 부분 굽힘 > 주먹 순서의 검지 직진도
- 핀치에서 엄지–검지 정규화 거리 감소
- 거울 자세의 좌우 손에서 일관된 손바닥 법선
- 양손 거리·방향·마주 보기와 서로 다른 손 크기 계산
- 잘못된 입력의 명시적 오류와 중심 일치 시 안전한 optional 결과

## #5 연결 체크리스트

#5의 ARKit 어댑터는 특징 계산 코드와 분리하고 다음을 확인한다.

- `HandAnchor.chirality`를 `HandSide`에 매핑한다.
- [`originFromAnchorTransform`](https://developer.apple.com/documentation/arkit/handanchor/originfromanchortransform)과 [`anchorFromJointTransform`](https://developer.apple.com/documentation/arkit/handskeleton/joint/anchorfromjointtransform)을 올바른 순서로 곱한 뒤 translation 열만 월드 위치로 전달한다.
- 좌표 단위가 모든 관절과 양손에서 동일한지 확인한다.
- ARKit 관절 이름을 같은 이름의 `HandJoint`에 매핑한다.
- `handSkeleton`이 없거나 필요한 관절을 전달할 수 없으면 불완전한 `HandSample`을 정상 표본처럼 사용하지 않는다.
- [`Joint.isTracked`](https://developer.apple.com/documentation/arkit/handskeleton/joint/istracked)는 가림 상황에서도 plausible transform을 줄 수 있으므로, 무조건 제외할지 유지할지는 실기기 관찰 후 별도로 결정한다.
- 왼손/오른손, 손바닥 앞·뒤, 손 크기, 손가락 벌림, 가림과 추적 손실 데이터를 저장해 세 정규화 후보를 비교한다.
- 두 HandAnchor가 다른 시점에 갱신될 수 있으므로 양손 특징에 사용할 시간 차 허용 범위는 후속 구현에서 정한다.

## 한계와 다음 확인

- 합성 좌표는 실제 관절 노이즈, 해부학적 차이, 가림과 ARKit의 추정 transform을 재현하지 못한다.
- 손가락 직진도만으로 옆으로 벌린 손가락과 원하는 포즈를 구분할 수 없다.
- 굽힘 각도는 거리보다 손 크기에 덜 민감하지만 짧은 뼈 구간의 위치 오차에 민감할 수 있다.
- 손바닥 법선은 세 기준점이 거의 일직선이면 계산할 수 없으며, 실제 손바닥 앞·뒤 의미가 기대와 맞는지 실기기에서 확인해야 한다.
- 기하평균 정규화는 균일 스케일 합성 입력에서는 유지됐지만 실제 사용자 사이에서 가장 안정적인 기준이라는 결론은 아니다.
- 실제 임계값, 여러 프레임의 안정화와 최종 Pose 분류는 #5의 좌표를 연결한 후 별도 `[DECISION]` 또는 `[TUTORIAL]` Issue에서 다룬다.

## 결론

ARKit 타입 없이도 합성 관절 좌표에서 한 손과 양손 특징을 계산하고, 손의 평행이동·회전·균일 스케일에 대한 성질을 단위 테스트로 재현할 수 있었다. 따라서 본편 4장 특징 계산의 후보로는 사용할 수 있지만, 정규화 방식과 분류 임계값의 채택은 실기기 좌표 비교 전까지 보류한다.
